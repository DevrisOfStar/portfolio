# 블로그 관리자 정책

## 목표 동작

- 블로그 작성 UI는 로컬 개발 클라이언트에서만 접근할 수 있다.
- 로컬 작성 UI에서 게시한 글과 이미지는 프로덕션 Workers를 통해 production D1과 R2에 저장한다.
- 프로덕션 공개 사이트에는 작성 UI와 관리자 API 키를 제공하지 않는다.

## 인증 정책

- 관리자 쓰기 요청은 `X-API-Key` 헤더를 사용한다.
- 백엔드는 Cloudflare 환경의 `ADMIN_API_KEY`와 요청 헤더를 비교한다.
- 키가 없거나 일치하지 않으면 `401 Unauthorized`로 거부한다.
- 실제 키 값은 Git, 문서, 프로덕션 프론트엔드 번들에 포함하지 않는다.
- 로컬 클라이언트의 `VITE_ADMIN_API_KEY`는 관리자 개인 개발 환경에서만 사용한다.

## 접근 범위

- 공개 읽기 API는 인증 없이 사용할 수 있다.
- 관리자 쓰기 API는 유효한 API 키가 있어야 한다.
- CORS 허용 여부는 인증을 대신하지 않는다.
- 로컬 작성 클라이언트의 허용 Origin은 `http://localhost:5173`, `http://127.0.0.1:5173`, `http://localhost:4173`, `http://127.0.0.1:4173`이다.

## 저장 대상

- 프로덕션 Workers의 관리자 API를 호출하면 production 환경에 바인딩된 D1과 R2를 사용한다.
- 로컬 Workers를 호출하면 로컬 또는 개발 환경 바인딩을 사용하며 프로덕션 저장 완료로 간주하지 않는다.

## 현재 코드와의 불일치

- `backend/src/utils/auth.ts`는 유효한 API 키를 검사하기 전에 요청 URL 호스트를 검사한다.
- 프로덕션 Workers 호스트는 localhost가 아니므로 목표 동작이 차단된다.
- 후속 구현에서는 작성 UI의 로컬 전용 정책은 유지하면서, 프로덕션 관리자 API는 API 키 인증 후 쓰기를 허용하도록 인증 경계를 정합화해야 한다.

## 완료 조건

- 로컬 개발 클라이언트의 유효한 관리자 요청이 production D1/R2에 저장된다.
- 누락되거나 잘못된 API 키 요청은 저장되지 않는다.
- 프로덕션 공개 사이트에서 작성 화면과 관리자 키를 사용할 수 없다.
- 글 작성과 이미지 업로드 각각에 대해 성공 및 인증 실패 테스트가 존재한다.
